## 3) قاعدة البيانات والهجرات

- **قاعدة فارغة:** `test:bootstrap` 69/69 — كل الجداول/الأعمدة المطلوبة تُبنى قبل فتح المنفذ، و**خادمان متزامنان** على قاعدة فارغة يقلعان بأمان (بلا قفل هجرات — idempotent بالتصميم).
- **قاعدة legacy:** كل حزم التكامل (18 حزمة) تعمل على قاعدة التطوير القائمة ببياناتها القديمة — لا حذف/تغيير لأي بيانات قديمة (الهجرات إضافية حصريًا).
- **قاعدة جزئية:** مُختبَر عمليًا — حذف جدولين + عمود `tracking_mode` ثم إقلاع → **اكتمل المخطط ذاتيًا** و`/ready` عاد 200.
- **ALTER على الجداول الكبيرة:** إضافة عمود ENUM لحظية (instant)؛ الفهرس الجديد يُبنى online (~0.8s/100k صف).
- **Unique/FK:** فُرادى الدفعات (item+lot_norm)، الأرصدة (wh+lot)، الحركات (seq+lot)، أرقام المستندات — كلها UNIQUE. FKs جداول الدفعات تطبيقية (R2) وpreflight يكشف اليتامى.
- **Dry-run:** scope backfill وmigrate-purchase-lots كلاهما dry-run افتراضيًا مع تقرير مطابقة، ولا يمسّان المخزون.
- خطة الاستعادة/التعطيل: runbook مخصص (ثلاث درجات).

## 4) المصالحة (Preflight)

`npm run warehouse:v2:preflight` — 22 فحصًا (BLOCKER/WARNING/INFO)، **تقرير فقط**، خروج غير صفري عند أي BLOCKER، `--json/--csv`. يغطي كل بنود المتطلب: مخزون↔دفعات، مُتتبَّع بلا دفعات، أرصدة سالبة، GL غير متوازن، قيود بلا مستند، حركات بلا مستودع/صنف، مستندات بلا تدقيق، تحويلات قيد العبور، جرد بلا تسوية، SKU مكرر/فارغ، أصناف غير نشطة بمستندات مفتوحة، إسنادات النطاق والمستخدمون الممنوعون، لقطة إجماليات اللوحة/التقارير مع فحص تماثل.
**النتيجة على قاعدة التطوير: BLOCKER = 0** (تحذيران مشروعان: 3 أصناف قديمة بلا SKU + مستخدم بلا إسناد). اختبار الحقن: انحراف مصطنع يُكشف فورًا كBLOCKER ويُفشل البوابة.

## 5) التوافق مع النظام القديم

- الواجهة القديمة على `/` تعمل (تُخدَم بلا مساس)؛ POS/المبيعات/الهدر يمرّون عبر `deductWarehouseStock` **المُدرك للدفعات** (FEFO + ثبات) — lotWriters 12/12.
- **رفض استلام شراء قديم لصنف مُتتبَّع:** رسالة عربية واضحة توجّه إلى استلام v2، **422 بلا أي مخزون/حركة جزئية** (مُثبَت قبل/بعد بالأرصدة).
- **نتيجة تدقيق أُغلقت في 5A:** أربعة مسارات قديمة إضافية كانت قادرة على تغيير كمية صنف مُتتبَّع خارج دفتر الدفعات (`stock-update`، الجرد القديم، تسجيل بكمية، `receive-approve`) → حارس مركزي يرفضها الآن بنفس الرسالة، والأصناف غير المُتتبَّعة بلا أي تغيير سلوكي (اختبارات رجعية خضراء).

## 6) Feature Flags وخطة القطع

- `WAREHOUSE_V2_ENABLED` (جديد): تعطيل آمن — صيانة للـSPA + 503 لكتابة v2 + بقاء القراءة والقديم (اختبار 4/4). لا يكتب النظامان نفس الوثيقة أبدًا: عند التفعيل تُمنع الكتابة القديمة للمُتتبَّع، وعند التعطيل تُمنع كتابة v2 كلها.
- `WAREHOUSE_SCOPE_ENFORCE`: بوابة الطيار — الإسناد عبر `user_warehouse_access` يحدد مَن يرى/يعمل (admins دائمًا)؛ preflight يسرد من سيُمنع قبل التفعيل.
- لم يُفعَّل أي شيء في الإنتاج (عمل محلي بالكامل، بلا push).
