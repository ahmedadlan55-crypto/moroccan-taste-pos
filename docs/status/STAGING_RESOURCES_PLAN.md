# خطة موارد Staging — الحساب قبل/بعد وخطة الإيقاف

> **لا يُحذف أي مورد دون أمر صريح من المالك.** هذه وثيقة حساب وخطة فقط.

## 1. الوضع الحالي (أثناء التطوير والمراقبة)

| المورد | الدور | الحالة | كلفة تقريبية* |
|---|---|---|---|
| Railway Production (خدمة + MySQL) | النظام الحي — main | **يبقى دائمًا** | التكلفة الأساسية |
| prod-monitor (مراقبة سحابية كل 5 دقائق) | مراقبة موجة Canary الأولى | يعمل حتى إغلاق تقرير الـ 24 ساعة | هامشية |
| warehouse-staging (خدمة) | تحقق ما قبل الموجات | مطلوب حتى اعتماد الموجة التالية | خدمة ثانية مدفوعة |
| Staging MySQL (+Volume) | قاعدة التحقق | مرتبط بالخدمة أعلاه | تخزين مدفوع |

\* الأرقام الفعلية تُقرأ من لوحة Railway → Usage (لا يمكن قراءتها من هنا دون توكن CLI صالح — memory: توكن railway ينتهي ويتطلب login تفاعليًا).

## 2. المبدأ المعماري المُسلَّم (لا تكلفة إنتاج مزدوجة)

- **مستودعات + كاشير V2 داخل نفس الخدمة**: build واحد (Dockerfile يبني SPA المستودعات ثم SPA الكاشير في نفس الصورة)، Express واحد، قاعدة واحدة، Auth واحد.
- لا خدمة إنتاج ثانية، لا دومين مستقل، لا قاعدة مستقلة — **صفر تكلفة إضافية دائمة** لأي من النظامين.

## 3. شروط الإيقاف (كلها يجب أن تتحقق قبل التنفيذ)

1. اكتمال Warehouse ✅ (تقرير البوابة) + اكتمال Cashier V2 (تقرير البوابة الثاني).
2. نجاح UAT من المالك.
3. اكتمال النشر التدريجي (كل الموجات) واستقرار Production.
4. أرشفة تقارير المراقبة + Backup نهائي لقاعدة Staging (mysqldump إلى تخزين خارجي) إن كانت تحمل بيانات تحقق يُحتاج الرجوع إليها.

## 4. خطة الإيقاف (بأمر المالك، بالترتيب)

| # | الإجراء | الأثر | Rollback |
|---|---|---|---|
| 1 | إيقاف prod-monitor (بعد إغلاق تقرير 24h واعتماد الموجة) | توقف الفحص الدوري | إعادة تفعيل الخدمة/الجدولة |
| 2 | أخذ mysqldump نهائي من Staging MySQL وحفظه خارجيًا | لا شيء | — |
| 3 | إيقاف خدمة warehouse-staging (Sleep/Remove) | تتوقف فوترة الخدمة | إعادة النشر من الفرع (build من git) |
| 4 | حذف Staging MySQL + الـVolume | تتوقف فوترة التخزين | استعادة من dump الخطوة 2 |

**الحساب بعد الإيقاف:** يتبقى فقط Railway Production (خدمة واحدة + MySQL واحد) — أي العودة إلى خط الأساس التاريخي للتكلفة، مع نظامين كاملين (مستودعات + كاشير) داخله.

## 5. كيف يقرأ المالك الأرقام الفعلية

Railway Dashboard → Project → Usage: صف لكل خدمة (vCPU/RAM/Volume). قبل التنفيذ سجّل لقطة "قبل"، وبعد الخطوات 1-4 سجّل "بعد" — الفرق هو الوفر الشهري الكامل لموارد Staging.
